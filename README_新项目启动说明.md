## 1. 这个新项目要做什么

**软件逻辑与业务规则完全不变**，变的是**感知手段**：

| | 源项目（保底） | 新项目 |
|---|---|---|
| 看屏幕 | 外接 USB 摄像头拍屏幕 | **iMouse 投屏 API 抓屏** |
| 图色/模板 | 相机像素空间匹配 | **设备屏幕坐标空间**匹配（原生分辨率） |
| OCR | raw 帧 ROI | **原生截图**（更清晰、更快） |
| 操作 | **机械臂**（HTTP:8082） | **机械臂**（不变） |

**为什么还保留源项目**：
投屏是**过渡手段**，官方可能后期限制。源项目是保底版本，
一旦投屏不可用必须能切回"纯摄像头 + 机械臂"。**源项目不能废弃**，
新项目结束后还要回去继续优化升级。

## 4. ⚠️ 最容易踩的坑：投屏**不解决**"点得准"

投屏解决了**视觉侧**（看得准），但**执行侧**没解决：

```
屏幕坐标（投屏直接给，已知）  ──?──>  机械臂坐标（物理设备，仍需标定）
```

**必须做的事**：采用源项目已定稿的标定方案（`docs/方案_标定体系重设计.md` 第 ② 层）：

> 手机全屏显示已知靶点（网页 / App）→ 机械臂去点
> → **手机上报真实触摸坐标** → 得到「目标屏幕坐标 ↔ 实际触点」→ 拟合双线性模型

收益：标定从"三步手工 1~2 小时" → "1~2 分钟"，精度 ≤3px。

## 5. 实施顺序建议

| 阶段 | 内容 | 验收 |
|---|---|---|
| 1 | 打通 iMouse 抓屏，替换取帧源（保留 `FrameSource` 抽象以便切回摄像头） | 能稳定取到帧 |
| 2 | 模板与 ROI 迁移到**设备屏幕坐标** | 页面判定正常 |
| 3 | OCR 换原生截图，调 `det_limit_side_len` | 字段抽取率不降、耗时下降 |
| 4 | **机械臂映射标定**（网页/App 上报触摸坐标） | 落点 ≤3px |
| 5 | 全链路回归：桌面 → 列表 → 详情 → 抢单 | 用 `dry_run + review_mode` 先跑通 |
| 6 | 提速（按行 ROI、消除重复 OCR、按需读第二屏） | 复用 `方案_扫描与OCR提速.md` |

## 6. 环境与铁律

- Python 3.11；机械臂走 `http://127.0.0.1:8082/MyWcfService/getstring`
- **`dry_run` 与 `review_mode` 默认必须开启**（只记录/暂停等人工），跑通后再放开
- **改配置前先备份**；每个新功能做成可开关，不达标立即关
- **先 import onnxruntime 再 import PyQt5**（顺序反了会 DLL 冲突）
- 保留摄像头模式作为降级路径
