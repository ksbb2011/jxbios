## 2) 反思 —— 根因 / 是否踩已知坑（对照 docs/交接文档/06）

1. **进详情→检测 detail 状态 ≈11s（占详情停留 65%）**：detect 每帧匹配多模板慢 + 详情页加载。属全局速度瓶颈，对应 06·D4（详情重复检测）精神。**尚未修**，是下步首要提速点。
2. **方数大量 None**：OCR 常漏读，但不影响判定（拼单才用）。低风险。
3. **缓存命中后缺「返回快速比对列表是否变化」**：当前仅上滑清缓存；同屏返回若 App 已刷新列表，缓存坐标可能错位 → 潜在误点。需补轻量比对。
4. **source_red 首刷仍偶发未命中**：靠 `back_to_top` 兜底（06·B3 阈值卡线）。持久项。
5. **detect 每帧 1~2s** 全局瓶颈：建议按当前状态只匹配相关模板。

## 3) 优化建议（性能 / 鲁棒性 / 可观测性）

- **性能**：降 11s 检测延迟——点进详情后用单一「返回箭头」模板快速确认、详情加载期跳过全量 detect、缩短 `wait_state` 超时。
- **鲁棒性**：缓存命中加「返回后列表轻量比对」，防 App 刷新导致坐标错位；`source_red` 补变体/调阈值减少兜底依赖；`idle` 反风控改随机概率触发更拟人。
- **可观测性**：`tools/analyze_runs.py` 增「淘汰原因分布」统计（昨日 7.5 已提，仍待做）；`data/traces/` 留证截图已就位，建议附「判定原因」文本索引便于回放。
