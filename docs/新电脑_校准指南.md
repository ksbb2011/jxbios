# 新电脑校准指南（2026-09-13 整理）

> 配套：`docs\新电脑_环境安装配置.md`（先把程序和外部组件装好，再来做校准）
> 工具：**`校准工具.exe`**（exe 版，控制台菜单）/ **`标定工具.bat`**（源码版菜单）

---

## 0. 先判断你是哪种场景

| 场景 | 特征 | 要做什么 |
|---|---|---|
| **同工位换主机** | 机械臂、手机支架、笔都没动，只换了电脑 | 装环境 → 确认取帧画面 → **复检**（约 1 分钟）。超差才重标 |
| **全新工位** | 机械臂 / 手机重新摆放、换笔、换手机 | 归位 → 测 z_press → 映射标定 → 复检 → UI 落点校准 → 截图确认 |

---

## 1. 为什么大部分标定"不用重做"

因为绝大多数资产是**手机屏幕坐标空间**里的量（iPhone X = **375 × 812 逻辑点**），与电脑无关：

| 资产 | 存放位置 | 换电脑要重做？ |
|---|---|---|
| 模板图（40+ 张） | `data\templates\` | ❌ 不用 |
| 模板定义 / 归一化区域（听单检测区、城市面板、列表页…） | `config\templates.json`、`config\regions.json` | ❌ 不用 |
| 字段偏移（卡片内各字段相对位置） | `config\fields.json` | ❌ 不用 |
| 页面判态阈值 | `config\thresholds.json` | ❌ 不用 |
| 控件坐标 | `config\coords.json` | ❌ 不用 |
| **机械臂映射 `actuation`（像素 → 机械臂坐标）** | `config\hardware.json` | ✅ 依赖机械臂与手机的**物理位置** |
| **下压深度 `z_press`** | `config\hardware.json` | ✅ 依赖笔尖与屏幕的**实际间隙** |
| 取帧源 / 分辨率 / 旋转 | `config\vision.json` → `capture` | ⚠️ 换电脑要**确认**；换取帧源则必须全部重做 |
| 按钮落点偏差 | 测量记录 `data\ui_tap_calib.json` | ✅ 需要时重测 |

**结论：同工位换主机，把 `config\` 与 `data\templates\` 直接拷过去即可**，真正要确认的只有取帧画面 + 复检。

---

## 2. 同工位换主机：照着做

1. 拷整个 `dist\运满满抢单机器人\`（含 `config\` 与 `data\templates\`）—— 见环境安装配置文档。
2. `校准工具.exe imouse` 探活：投屏在线、能截图、分辨率 375×812。
3. 打开主程序 → 点「截图留存」→ 打开 `data\shots\` 里的图，确认：
   - 画面是**正的**；歪了 → `config\vision.json` → `capture.camera_rotation`
   - 尺寸是 375×812；不对 → `capture.capture_resolution` 与 `capture.fast_size` 都应为 `[375, 812]`，`capture.source` 应为 `imouse`
4. `校准工具.exe verify` → 复检映射精度（**只验证、不写配置**，约 1 分钟）。
   - mean / max ≤ **3pt** → 通过，收工。
   - 超差 → 按第 3 节重跑映射标定。

## 3. 全新工位：照着做（顺序不要颠倒）

> 映射标定前，手机请停在「**备忘录 → 标记 → 第 3 个笔 → 空白画布**」（工具靠截图找**墨点**）。

| 步骤 | exe 版（菜单编号 / 命令） | 源码版命令 | 验收标准 |
|---|---|---|---|
| ① 机械臂归位 | 菜单 1 / `校准工具.exe home` | `py -3.11 tools\arm_home.py` | 抬笔回原点、不挡摄像头 |
| ② 测下压深度 | 菜单 2 / `校准工具.exe scanz` | `py -3.11 tools\calibrate_arm_ink.py --scan-z --z-start 5.5 --z-max 8.0 --z-step 0.1 --up-float 1.5` | 找到"最轻能触发触屏"的档位，再加 1~3mm 上浮；自动写入 `z_press` |
| ③ 映射标定 | 菜单 3 / `校准工具.exe ink --z-press <②的值> --grid 8 --rounds 2` | `py -3.11 tools\calibrate_arm_ink.py --z-press <②的值> --grid 8 --rounds 2 --auto-restart` | 拟合双线性 `actuation`；**验收不通过不会写入** |
| ④ 复检 | 菜单 4 / `校准工具.exe verify` | `py -3.11 tools\calibrate_arm_ink.py --verify-only` | 多点验收 mean / max ≤ **3pt**（历史实测 0.95 / 1.57） |
| ⑤ UI 落点校准 | 菜单 7 / `校准工具.exe tap` | `py -3.11 tools\calibrate_tap_ui.py` | 5 个目标逐个测；期望点命中，或偏差 ≤ 1 个步长（6pt） |
| ⑥ 截图确认 | 主程序里点「截图留存」 | 同左 | 画面正、375×812 |

⚠️ **Z 安全红线：`z_press` 硬上限 6.2**（越大压得越深，超过会点碎屏幕）。工具已硬钳制，
手动改 `config\hardware.json` 时也不要越线。

⚠️ **重标后必须同步 `arm_range`**（`config\hardware.json` → `calibration.arm_range`）：
按新的 `actuation` 重算屏幕四角映射。不同步就会出现 2026-09-10 那次"屏幕左上角被错误
clamp → 返回箭头点不到"。算法见该文件里的 `_note_arm_range_fixed`（四角映射示例齐全）。

## 4. UI 落点校准（2026-09-13 新增）—— 解决"按钮点不动"

**为什么需要**：墨点标定要求画面里能看到墨点，而屏幕上下边缘被 App 的按钮栏 / 画笔栏挡住，
**没法用墨点校准**。所以这里改用 **App 自身的可见反应**当反馈。

- **判据**：点中 → 整屏变化 ≥ 1.0%；没点中 → ≤ 0.13%（两组相差 15 倍以上）。
- **策略**：**期望点优先 → 逐环外扩（默认 6pt 步长、最远 ±24pt）→ 首次有反应即停**。
  那个点与期望点的差，就是该按钮的落点偏差。
- 一次性动作（清空筛选 / 确认 / 返回）点成功一次状态就变了 → **一次运行 = 一次测量**；
  要重复测就重新摆页面再跑。
- 「清空筛选」用**语义判据**最稳：确认按钮 **正红 → 浅红**（与 App 自身的
  `confirm_button_clickable` 同一口径，不靠整屏差分）。
- 本工具**只测量、绝不改配置**；结果**追加**写到 `data\ui_tap_calib.json`。

常用命令：

```
校准工具.exe tap                       # 菜单（推荐，页面由人工摆好）
校准工具.exe tap --list                # 看 5 个目标与各自的前置条件
校准工具.exe tap back_to_top --wait    # 等你摆好页面按回车再开始
校准工具.exe tap --step 3              # 更细步长（±3pt），能测得更准
```

5 个目标：`back_to_top`（返回顶部）、`source_red`（全国货源 Tab）、`city_clear`（清空筛选）、
`city_confirm`（确认，正红）、`detail_back`（详情页返回）。

**结果怎么用**：把记录汇总后判断某区域是否超差。若某区域长期偏差 > 1 个步长，再决定加
"残差补偿"（补偿写入 `config\hardware.json` 后，主循环会自动热重载并 `arm.reload_config()`，
**不需要重启程序、也不需要重新打包**）。

## 4.1 整屏网格标定（2026-09-13 新增）—— 精度最高的一条路

**为什么要它**：前两条路各有硬伤 ——
墨点标定的画布只能取 **y≈170~660**（备忘录上下被按钮栏挡住、留不下墨点），
屏幕上下边缘（含底部那排「清空筛选/确认/返回顶部」）只能靠模型外推，实测**统一偏左 6~7pt**；
UI 落点校准一次只测 1 个按钮、依赖页面状态、还受 6pt 步长量化。

**整屏网格标定**则让**手机 App 当传感器**：机械臂在整屏 45 点逐点压下，手机把每次被压到的
**真实坐标**上报回来 → 电脑重拟合 `actuation` + 重算 `arm_range` + 生成整屏 `tap_correction`
锚点。整屏无死角、无状态依赖、无步长量化，一轮约 6 分钟。

### 前置条件（缺一不可）

1. 手机端 App 已编译安装：见 **`ios_calib/README.md`**（Xcode + 免费 Apple ID 即可，7 天有效期）。
2. 手机与电脑**同一 Wi-Fi**；Windows 防火墙放行入站 **8767**。
3. 手机「自动锁定」设**永不**（App 也会主动禁锁屏，双保险）。
4. 标定期间**别用手碰屏幕**（手点的坐标会被当成机械臂落点）。

### 三步走

```powershell
$env:PYTHONPATH=(Get-Location).Path     # 从仓库根跑时先设一次
py -3.11 tools\calibrate_full_grid.py --list    # ① 看布局/建议 radius/预计耗时（不碰硬件）
py -3.11 tools\calibrate_full_grid.py --dry     # ② 只验连通（不驱臂）：App 里填电脑地址
py -3.11 tools\calibrate_full_grid.py           # ③ 正式一轮：只测量，不写配置
py -3.11 tools\calibrate_full_grid.py --verify  # ④ 复压验收：给出补偿后误差
py -3.11 tools\calibrate_full_grid.py --verify --apply   # ⑤ 确认数据合理后写回配置
```

`--apply` 会写三处并自动备份（`hardware.json.bak_grid`）：
`calibration.actuation`（重拟合）、`calibration.arm_range`（按新模型重算）、
`calibration.tap_correction`（本次锚点）。
⚠️ 它会**丢弃别的工具在旧映射下测的锚点**（refit 后方向已失效）——想保留加 `--keep-foreign-anchors`。

### 三个期望的数字（判据）

| 轮次 | 含义 | 期望 |
|---|---|---|
| 第 1 轮 | 旧模型下的残差（= 要修的量） | 数值本身不重要，看是否**远大于 3pt** |
| 第 2 轮 | 新模型自检（不带补偿） | 明显小于第 1 轮（线性系统偏差已被模型吸收）；**锚点依据只看这一轮** |
| 第 3 轮 | 补偿后（= 运行时真实精度） | **max ≤ 3pt**（离线自测实测：mean 0.09pt / max 1.33pt） |

> 为什么必须看第 2 轮才建锚点：新模型已经吸收了系统性偏差，若拿第 1 轮残差建锚点，
> 运行时就会**补两次**（5.8pt 的偏差被补成反方向 5.8pt，比不补更糟）。这是实测踩出来的坑。

### 不想上真机先验？跑离线自测

```powershell
py -3.11 tools\calib_mock_phone.py
```
假手机 + 假机械臂真跑 HTTP 协议，13 项断言覆盖"采样 → 拟合 → 两层补偿分工 → 写盘 → 备份"，
且**真实配置零改动**。任何一项不过都会打印原因。

### 排障

| 现象 | 处理 |
|---|---|
| App 一直"未连接" | 防火墙 8767 / 不同网段 / Info.plist 的 ATS 与本地网络权限 / 手机设置里未允许"本地网络" |
| 电脑端报"未收到手机上报，已中止" | 同上；另查手机是否熄屏、App 是否被切后台 |
| 残差异常大（几十 pt） | 多为 App 画布没铺满：底部诊断行里"画布/窗口"两个尺寸应一致（≈375×812） |
| 第 3 轮仍 >3pt | 网格太稀（`--cols 6 --rows 10`，耗时线性增加）；或机械臂重复定位差（先跑菜单 1/2/4 复检） |
| 手机没编译好、只想验电脑侧 | `py -3.11 tools\calib_mock_phone.py --client http://127.0.0.1:8767`（配合 `--dry`） |

## 5. 触发条件速查：换了什么 → 重做什么

| 变了什么 | 必须重做 |
|---|---|
| 只换电脑主机（机械臂 / 手机 / 笔都没动） | 确认取帧画面 + **复检** |
| 换笔（粗细不同） | **z_press** + 映射标定 + 复检 |
| 机械臂重新摆放 / 挪支架 / 换桌面 | 映射标定 + 复检 |
| 换手机 / 手机壳 / 贴膜 | 映射标定 + UI 落点校准 + 模板与归一化 ROI 重采 + 字段偏移 |
| 换取帧源（iMouse ↔ 摄像头 ↔ 采集卡） | **全部标定重做**（`vision.json` 里注明：亮度分布 / 分辨率 / 黑边全变） |
| 运满满 App 改版 | 模板重采 + 页面判态阈值重定 |
| 某个按钮点不中 | UI 落点校准（只测那一个目标即可） |
| 想**整屏**提升落点精度（尤其屏幕底部那排按钮） | 整屏网格标定（`校准工具.exe grid`，需先用 Xcode 编译 `ios_calib` 的 App）——见 4.1 节 |
| **断电 / 重新上电** | 先 `home` → `校准工具.exe verify`；超差 → 重标映射（顺手必做：复测 `z_press`；重标后同步 `arm_range`）。详见第 7 节 |

## 6. 出问题怎么查

| 症状 | 先看 |
|---|---|
| 某个按钮点不中 | `data\ui_tap_calib.json` 里该目标的 `trials`（每次尝试的整屏变化值，能看出是"完全没反应"还是"差一点"） |
| 点击整体偏移 | `校准工具.exe verify` 的 mean / max；`config\hardware.json` → `calibration.actuation` |
| 机械臂连不上（`open_port` 返回资源号 0） | 串口服务被占 → `Restart-Service JxbService -Force`（管理员）或先跑 `校准工具.exe home` |
| OCR 失效、页面判态退化（不点红色「全国」、不清筛选、乱滑） | `data\gui_boot.log` 三条判据 + `data\logs\run_*.log` 里的「无 OCR 结果，回退静态默认」 |
| 标定中途中断 | 工具自带退出保护（抬笔 / 复位 / 释放串口）；若串口仍被占，重启服务后再跑 |

## 7. 关机 / 断电规程（2026-09-13 补充，重要）

### 7.1 断电前必做

1. **先抬笔**：跑 `校准工具.exe home`（= 抬笔 `Z0` → 复位 `X0Y0Z0` → 释放串口）。
   别让笔尖一直压着屏幕（`z_press` 是"压着"的状态），长时间压着对屏幕和笔都不好。
2. **让程序优雅停止**：用 GUI 的停止按钮，或等本轮自动收工；别在"正在下压"的动作中途拔电。
3. 然后断电。标定参数都落在 `config\hardware.json`，**断电不会丢**。

### 7.2 上电后必做

1. 机械臂先通电、等它就位；iMouse 投屏保持在线。
2. **很可能**出现 `open_port` 返回**资源号 0**（串口被占）——这是断电后**必然会遇到**的：
   跑 `校准工具.exe home` 会自动弹 UAC 重启 `JxbService`；或手动
   `Restart-Service JxbService -Force`。
3. **先 `home`，再 `校准工具.exe verify`** 复检。超差才重标（见 7.4）。

### 7.3 断电会不会让坐标失效？—— 取决于"0,0 的物理含义"

代码里能确认的（`core/devices/arm.py`）：

- 每次**连接**都会发 `X0Y0Z0`（复位）验证通信；每次**关闭**也发 `X0Y0Z0` 再释放串口；
- `actuation` 是"手机像素 → 机械臂坐标"的**固定映射**，它成立的前提是
  **机械臂的 `X0Y0` 在物理上是可复现的同一个点**；
- 协议里只有 5 条指令（`X{x}Y{y}` / `Z{z}` / `Z0` / `X0Y0Z0` / 释放），
  **没有"读当前位置"的指令**；仓库里也没有该控制器的硬件文档。

所以"`X0Y0Z0` 是真回限位找零，还是把当前位置记作 0"**只能实测判定**：

| 测试 | 怎么做 | 判据与结论 |
|---|---|---|
| A. 复位可重复性（不断电） | `home` → `校准工具.exe verify` | ≤3pt：复位可靠；超差：机械臂本来就偏了 |
| B. **断电可重复性（关键）** | `home` → 断电 → **不碰任何东西** → 上电 → `home` → `verify` | ≤3pt：原点是**绝对**的（回零到限位）→ 以后随便断电；几十 pt 起：原点是**相对**的 → 每次上电后必须重标映射 |
| C. 直观探针（不想等 B 时） | 上电重连后跑 `校准工具.exe tap source_red --wait`（"全国货源"Tab 可反复点，是天然探针） | 能点中（Tab 变红）：落点没漂；点不中/偏移：已经漂了 |

> 单纯断电、**没人碰、没有位移**时，步进电机静态位置通常不变；
> 真正会毁掉标定的是"断电期间被人推/撞了笔架横梁"。

### 7.4 断电后真的漂了怎么办

| 处置 | 说明 |
|---|---|
| 首选：尽量别断电 | 平时只关程序、不断机械臂电源；或给机械臂做一个**机械挡块**，每次手动推到挡块再上电（治本） |
| 快速重标（约 3~5 分钟） | `校准工具.exe scanz` → `校准工具.exe ink --grid 6 --rounds 1` → `校准工具.exe verify` |
| ⚠️ **重标后必须同步 `arm_range`** | 重新标定后 `actuation` 变了，`calibration.arm_range` 要按新模型重算屏幕四角映射并同步。**2026-09-10 就吃过这个亏**：机械臂重新就位后 actuation 更新了、arm_range 没同步 → 屏幕左上角被错误 clamp → **返回箭头点不到**（详见 `config\hardware.json` 的 `_note_arm_range_fixed`） |

### 7.5 ⚠️ 断电后最先警惕的是 Z 轴（比 XY 更要紧）

- `z_press = 5.9` 是**机械臂坐标**，不是毫米；`z_calibration._note` 写明可用窗口只有 **0.6mm**
  （`5.6` 刚能触发 / `6.2` 是碎屏红线）。
- 如果断电后 Z 参考变了（笔架下沉、被人转动过），`5.9` 就可能变成"压更深"→ **有碎屏风险**。
- 所以断电重启后的**第一次动作**建议先跑 `校准工具.exe scanz` 复测；
  或至少临时把深度调低 0.1~0.2 试——宁可点不动，也别压过头。

### 7.6 禁止事项

- ❌ 断电期间用手推动笔架 / 横梁（这是唯一能"一次毁掉标定"的操作）。
- ❌ 在程序正在下压时拔电 / 强杀进程（会压着屏幕 + 串口被占）。
- ❌ 用加大 `z_press` 去"补偿"落点偏差（落点是 XY 的事，加 Z 只会压得更深）。

## 8. 重标 SOP（2026-09-13 现场实战版）

### 8.1 两条已实测确认的事实（别再猜）

1. **本机机械臂不支持自回零**：执行 `X0Y0Z0` 归位时**纹丝不动**（只回了个状态）⇒ 它是"把当前位置记作 0"。
   所以**零点只能靠物理重复**：断电/被碰后一定要回到同一个机械参考位置（推到底限位、或贴住挡块）。
2. **墨点标定的画布只覆盖 y≈170~660**（备忘录上下被按钮栏挡住，留不下墨点）⇒ 屏幕**底部按钮行**
   （清空筛选 / 确认 / 返回顶部 / 全国货源）只能靠模型外推，实测**统一偏左 6~7pt**：
   ```
   Δ( +0, +0) @(98,765) 确认按钮正红 True → True （整屏 0.30%）  ← 期望点：点不动
   Δ( -6, +0) @(92,764) 确认按钮正红 True → False（整屏 6.35%）  ← 往左 6pt：成功
   ```
   ⇒ 这就是"校准工具看着能点到、正式运行点了没反应"的真身：工具会**扫点**，运行只点期望点一次。
   修法见 8.3 的 `tap_correction`（已实现，配置里已有 4 个锚点）。

### 8.2 归位出现偏差后，完整重标步骤

| 步 | 操作 | 判据 / 注意 |
|---|---|---|
| 0 | **先把机械臂推回同一个物理参考位置**（限位/挡块）；关掉跑单程序（它占 COM4）；iMouse 投屏在线 | 这一步决定可重复性，别省 |
| 1 | `校准工具.exe` → 菜单 **1 归位** | 抬笔 + 清零 + 释放串口；报"资源号 0"会弹 UAC 自动重启服务 |
| 2 | 手机：**备忘录 → 新建 → 标记 → 第 3 个笔 → 空白画布** | 必须新页（旧墨点不产生差分 → 误报"未检测到"） |
| 3 | 菜单 **2 测下压深度**（上浮值填 **0.3**） | 目标 `z_press` **5.9~6.0**；>6.1 减小上浮；**6.2 是碎屏红线** |
| 3′ | ⚠️ 若映射已失效（笔戳到画布外） | **先做第 4 步**，等 XY 修好再回来测 Z，否则 Z 不可信 |
| 4 | 菜单 **3 跑映射标定**（z_press=5.9、grid 8、rounds 2） | 看验收行：`样本 16/16，mean/max ≤ 3pt`（历史 0.84 / 1.53） |
| 5 | `arm_range` | 菜单 3 成功后**已自动写入**并打印新旧值（2026-09-13 起）；若未生效见 8.5 |
| 6 | 菜单 **4 复检** | 独立验证：`16/16` + `mean/max ≤ 3pt` |
| 7 | 菜单 **7 UI 落点校准** → 测 5 个目标（返回顶部 / 全国货源 / 清空筛选 / 确认 / 详情返回） | 每个测完菜单会问"**是否应用补偿**"→ 选 Y，写进 `tap_correction` |
| 8 | **真程序验证**：启动 → 让它执行"设置路线" | 日志里应无 `网格未找到 XXX`；点击行出现 `补偿[city_clear -6,+0]` |
| 9 | 把 `dist\...\config\hardware.json` **拷回仓库 `config\`** | 否则下次重打包会冲掉本次标定 |

### 8.3 落点补偿 `tap_correction`（2026-09-13 新增）

- **配置**：`config/hardware.json` → `calibration.tap_correction`（`enabled` / `radius_px` / `points[]`）
- **生效方式**：`core/devices/arm.py::click_pixel()` 在点击前按"**半径内最近锚点**"平移几 pt
  （只影响点击，不影响滑动轨迹；只认实测锚点，未测区域一律不补）
- **写入口**：`校准工具.exe tap <目标>` 测完按提示回答 Y，或 `校准工具.exe tap --apply-all`
  （扫 `data/ui_tap_calib.json` 里各目标**最新一次**测量：偏移 ≥2pt 建锚点、≤1pt 自动清除旧锚点）
- **关闭**：把 `enabled` 改 false，或删掉 `points`（程序会当"不补偿"处理，绝不报错）
- **日志**：命中时打印 `点击像素 (98,764) 补偿[city_clear -6,+0] -> (92,764) 机械臂 (...)`

### 8.4 "不会再出现坐标偏差导致点击无效"= 四件套齐备

| 保障 | 由哪步负责 | 通过判据 |
|---|---|---|
| 落点准 | 菜单 3 + 菜单 4 | 复检 ≤3pt |
| 能触发 | 菜单 2 | `z_press` 5.9~6.0 |
| 边角不被钳 | `arm_range` | 四角 min/max 正确（菜单 3 自动写） |
| 按钮可点 | 菜单 7 + 应用补偿 | 5 个目标全部命中或已补偿 |

### 8.5 日常快检与排查工具

- **开机 30 秒快检**：`校准工具.exe tap source_red --wait` → 显示"期望点本身即可触发"就直接跑；
  报偏移就按 8.2 重走（注意：**断电不致命，位移才致命**）。
- **网格扫描诊断**（本次新增）：`py -3.11 tools\city_grid_scan.py 江苏`（或 `校准工具.exe run city_grid_scan.py 江苏`）
  → 先报"面板层级 = 根级/子级"，再逐步上滑打印每步 `Δ`（位移量）与是否升幅，失败时打印"本屏可见文字"。
  专门用来把"**层级不对**"和"**幅度不对**"这两类问题当场分开。
