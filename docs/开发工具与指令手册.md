## 0. 环境准备

### 0.1 🚀 最省事：双击 bat（推荐）

项目根目录有两个**内容完全相同**的 bat，双击即可运行，**不用记任何命令**：

```
标定工具.bat      ← 中文名（Windows 资源管理器原生支持，双击正常）
calibrate.bat     ← ASCII 名（脚本/远程调用时也安全）
```

菜单：
```
    1. 机械臂归位          （救急：卡住 / 串口被占时用）
    2. 测下压深度 z_press  （换笔、换手机后必做）
    3. 跑映射标定          （完整，3~10 分钟）
    4. 复检                （只验证精度，约 1 分钟，不重新标定）
    5. 单步探针            （戳一下看能否出墨点，排障第一步）
    6. iMouse 探活与实测
    0. 退出
```

打开时会**自动显示当前状态**：`z_press = 6.0`、`actuation = 已标定/未标定`。

> bat 内部有 `cd /d "%~dp0"`，会自动切到 bat 所在目录，
> 所以**无论从哪双击都能正常工作**，也会自动设好 `PYTHONIOENCODING` / `PYTHONPATH`。

## 2. 机械臂操作

### 2.1 `tools\arm_home.py` —— 归位（最常用）

```powershell
py -3.11 tools\arm_home.py                 # 归位；串口被占时自动弹 UAC 重启服务
py -3.11 tools\arm_home.py --no-restart    # 被占就直接报错，不弹窗
```

做了三件事：
1. 打开串口；若返回 0（被占）→ 自动 `Restart-Service`（弹 UAC）
2. 抬笔（`Z0`）→ 回原点（`X0Y0Z0`）
3. 释放串口

### 2.2 机械臂 HTTP 协议速查

```
基址：http://127.0.0.1:8082/MyWcfService/getstring

打开串口  ?duankou=COM4&hco=0&daima=0          → 返回资源号（带引号，如 "1572"）
移动      ?duankou=0&hco={id}&daima=X{x}Y{y}
下压      ?duankou=0&hco={id}&daima=Z{z}        （z 越大越深）
抬起      ?duankou=0&hco={id}&daima=Z0
复位      ?duankou=0&hco={id}&daima=X0Y0Z0
释放      ?duankou=0&hco={id}&daima=0
```

> ⚠️ 返回值是**带引号的 JSON 字符串**（`"1572"` / `"0"`），
> 必须 `int(r.text.strip().strip('"'))`，否则 `int('"1572"')` 直接 ValueError。

### 2.3 串口被占怎么办

| 现象 | 原因 | 解决 |
|---|---|---|
| `open 返回 0` | 上次进程被强杀没执行 close_port，WCF 一直占 COM4 | `arm_home.py`（自动重启）或管理员执行 `Restart-Service JxbService -Force` |
| `Restart-Service` 报"无法打开服务" | **权限不足** | 用管理员 PowerShell，或让 `arm_home.py` 弹 UAC |
| 暴力试资源号 `hco=xxx&daima=0` 无效 | 服务端资源映射已失效 | **只能重启服务**，别浪费时间试 |

## 3. 标定流程（核心）

### 3.1 流程顺序

```
① 手机停到「备忘录 → 标记 → 第 3 个笔（粗马克笔）→ 空白画布」
        ↓
② 扫 z_press（只需做一次，已写入 7.100）
        ↓
③ 跑映射标定（36 或 64 点 → 拟合双线性 → 10 点验收）
        ↓
④ 验收 ≤3px 才写入 config/hardware.json 的 calibration.actuation
```

### 3.2 已标定出的值

| 项 | 值 | 来源 |
|---|---|---|
| `z_press` | **6.000** | `min_z=5.600 + 加深 0.4mm`（⛔ 硬上限 **6.2**） |
| `actuation` | ⏳ **未标定**（流程被中断） | 待跑 |
| `arm_range` | `x[9.93, 73.2]` `y[16.62, 154.62]` | 源项目经验值，仅作首轮粗估 |

### 3.3 扫 z_press

> ⛔ **Z 越大 = 压得越深，硬上限 6.2，超过会点碎屏幕**（用户 2026-09-09 明确）。
> `--z-max` / `--z-start` / `--up-float` 全部被安全校验拦截，超限直接拒绝执行。

```powershell
py -3.11 tools\calibrate_arm_ink.py --scan-z --z-start 5.0 --z-max 6.2 --z-step 0.1 --up-float 0.4
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--z-start` | 5.0 | 起始 z（浅） |
| `--z-max` | **6.2** | 最深 z，**硬顶，超限拒绝执行**（旧文档 8.0 已废弃） |
| `--z-step` | 0.1 | 步长 |
| `--up-float` | **0.4** | 在 min_z 基础上加深量，**安全区间 [0, 0.6]**（旧的 1~3mm 在 6.2 硬顶下放不下） |

输出：`min_z=5.600 + 加深 0.40 → z_press=6.000（硬顶 6.200）`

### 3.4 跑映射标定

```powershell
py -3.11 tools\calibrate_arm_ink.py --z-press 6.0 --grid 6 --rounds 1 --auto-restart
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--z-press` | 6.0 | **必须用 --scan-z 实测值**；⛔ Z 越大越深，硬上限 **6.2**，超了碎屏 |
| `--grid` | 8 | 网格 N×N（6=36 点约 3 分钟；8=64 点约 10 分钟） |
| `--rounds` | 2 | 校准轮数（1 轮先验证，2 轮更准） |
| `--canvas` | `20 170 345 660` | **可点区**（iPhone X 备忘录红框，见下） |
| `--margin` | 0.0 | 网格在 canvas 内再向内缩的比例 |
| `--max-error-pt` | 3.0 | 验收阈值，**超了不写入** |
| `--ink-thresh` | 15 | 差分灰度阈值（细笔需降到 8~10） |
| `--min-area` | 2 | 墨点最小像素面积 |
| `--radius` | 90 | 第 1 级搜索窗口半径（第 2 级全屏兜底） |
| `--auto-restart` | 关 | 串口被占时自动弹 UAC 重启服务 |

### 3.5 其他模式

```powershell
# 探针：只在画布中心戳一下，验证能否出墨点（**排障第一步**）
py -3.11 tools\calibrate_arm_ink.py --probe-one --z-press 6.0

# 只验收：用已有 actuation 模型复检，不重新拟合
py -3.11 tools\calibrate_arm_ink.py --verify-only
```

## 4. 画布区域（**关键，别戳错**）

iPhone X 备忘录标记界面的**可点区只有中间红框**：

```
y 0-70      状态栏 + 标题栏
y 70-150    ← 「返回/撤销/重做/更多/完成」按钮栏   ⚠️ 戳到会退出界面
y 150-680   ✅ 可写画布（红框）—— 只有这里能画出墨点
y 680-770   底部画笔栏（6 个笔 + 颜色 + 粗细）      ⚠️ 戳到会切换工具
y 770-812   Home 指示条
x 15-350    可写区左右边界
```

**默认 canvas = `20 170 345 660`**（红框内再留 10~20px 安全边距）

> ⚠️ **踩过的坑**：早期默认 `15 110 360 700` 偏出红框，
> 网格点戳到顶部"完成"按钮**退出了标记界面**，
> 后续所有戳都失效（表现为"画布突然变干净、全部检测不到墨点"）。

### 画笔选择（第 3 个笔最合适）

| 工具位（左→右） | 笔迹 | 可检测性 |
|---|---|---|
| 第 1 个 | 极淡 1~2px | ❌ |
| 第 2 个 | 小圆点 3~4px | ⚠️ 勉强（需降 `ink-thresh` 到 8） |
| **第 3 个** | **粗横杠 ~30×5px，926px 墨迹** | ✅ **推荐** |
| 第 4 个 | 铅笔（对角线条纹） | — |
| 第 5 个 | 尺子 | — |

> 第 3 个笔画出的是**横杠**（扁笔尖），完全可用——
> 我检测的是**加权重心**，横杠的长轴像素多，定位比圆点更准。

| 项 | 值 |
|---|---|
| 版本 | **专业版**，HTTP `9912`（WS 9911） |
| 设备 | iPhone X（`iPhone10,3`），iOS 16.7.10 |
| 逻辑点 | **375 × 812** |
| 截图实际像素 | **375 × 812**（`ratio=1.0`，**无需坐标换算层**） |

| 键盘 `send_key` | ⚠️ **不支持中文**（只支持英文/数字/符号） |

### 5.3 两套 API 差异

| 能力 | XP 版 | 专业版（本机） |
|---|---|---|
| 设备列表 | `GET /api/device/get` → `data.list[]` | `POST fun=get_device_list` → `data{id:{...}}` |
| 截图 | `/pic/screenshot {id,jpg,rect}` | `get_device_screenshot {deviceid,isjpg,binary,original}` |
| 找图 | `/pic/find-image-cv` | `find_image {deviceid,img(base64)}` |
| OCR | `/pic/ocr` | `ocr` / `ocr_ex` |
| 找色 | `/pic/find-multi-color` | `find_multi_color` |
| 键盘 | `/keyboard/input` | `send_key {deviceid,key,fn_key}` |
| rect 格式 | `[l,t,r,b]` | `[[l,t],[l,b],[r,t],[r,b]]` |

> 专业版截图必须 `original=false`——`true` 返回高清图，**分辨率与手机不一致**。

## 8. 排查手册

### 8.1 检测不到墨点

按顺序排查：
1. **跑 `--probe-one`** —— 最小复现
2. 画布干不干净？戳在**旧墨迹上不产生差分**（工具会警告）
3. 是不是**退出了标记界面**？截图看顶部工具栏在不在
4. `dwell`/`settle` 够不够？**必须 1500/2000**，小于这个完全来不及留痕
5. `z_press` 够不够？跑 `--scan-z`
6. 画笔是不是第 3 个（粗的）？细笔只有 1~2px，检测不到
7. 调低 `--ink-thresh`（15 → 8）、`--min-area`（2 → 1）

### 8.2 墨点位置明显不对

- 偏差 (+7,+7) 左右 → **正常**，这正是标定要修正的系统性偏差
- 偏差 >50px → 可能**误检了 UI 变化**（戳到工具栏），检查 `--canvas`
- 偏差出现几百 px 的荒谬值 → 第 2 级全屏兜底误检，缩小 `--radius` 或提高 `--min-area`

### 8.3 机械臂不动 / 无响应

1. `arm_home.py` 归位试试
2. 检查串口是否被占（`open 返回 0`）
3. ⛔ 确认 z 在安全窗口内：**硬上限 6.2**（Z 越大越深，超了会**点碎屏幕**）。
   曾经以为"超过 8.5 才失效"并试到 8.5 —— 那是在直接怼屏，已废弃

## 9. 踩坑记录（**别重复踩**）

| # | 坑 | 根因 | 已修 |
|---|---|---|---|
| 1 | 64 点只检测到 10 个，误判"机械臂平面度问题" | **接触时长不够**：`dwell=150ms` 电容笔来不及留痕 | ✅ `dwell=2000ms`、`settle=1500ms` |

| 4 | 墨点明明有却检测不到 | 3×3 形态学开运算**把 3×2 的小墨点滤掉了** | ✅ 去掉形态学，改加权重心 |
| 5 | 探针报错但手动脚本能出墨点 | 探针里**硬编码了 150ms**，没走 InkCalibrator 参数 | ✅ 改用 `cal.settle_ms/dwell_ms` |

## 10. 关键设计约束（不可违背）

1. **iMouse 只做感知**（截图/图色/OCR），**所有操作由机械臂执行**
   - 唯一例外：线上沟通打字用 `send_key`（且**不支持中文**，需剪贴板方案）
2. **`core/domain/` 零改动**（业务规则与感知手段无关）
3. **默认 `dry_run=true` + `review_mode=true`**（不真抢单）
4. **投屏是反风控红线**：源项目 `frame_source.py` 明确标注「投屏/镜像=禁用」，
   本项目接受该风险，摄像头保留为降级分支
5. **测试通过才固化**——标定未完成前不写入 `actuation`
