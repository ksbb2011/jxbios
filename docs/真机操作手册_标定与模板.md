## 0. 前置检查（每次开工前必做）

### 0.1 重启机械臂串口服务（**不做会连不上 COM4**）

管理员 PowerShell：

```powershell
Restart-Service JxbService -Force
```

> 原因：进程被强杀不会执行 `close_port`，WCF 服务会一直占着 COM4，
> 下次 `open_port` 返回资源号 0。

### 0.2 确认手机状态

| 检查项 | 要求 |
|---|---|
| iMouse 控制台 | 手机**在线**（`state != 0`），AirPlay 已投屏 |
| 手机屏幕 | 停在**主屏 / App 资源库**（不要在锁屏、不要在设置里） |
| 自动锁屏 | 设置 → 显示与亮度 → 自动锁定 → **永不** |
| 手机亮度 | 调高，避免息屏 |

## 1. 第一次：把标定页加到 iPhone 主屏（**只需做一次**）

> ⚠️ **这一步是整个标定成败的关键。**
> 必须 Safari 打开后"添加到主屏幕"，再从主屏图标进入 —— 这样才是 **standalone 真全屏**，
> 可视区域才和运满满运行时一致。用 Safari 普通标签页会有地址栏，`innerHeight` 一直在变，
> 学到的坐标系天生是歪的。（iMouse 官方"鼠标参数采集"也是这么要求的。）

### 1.1 启动服务，拿到 URL

```powershell
cd f:\JXBproject\robot_order_picker_imouse
$env:PYTHONIOENCODING = 'utf-8'
$env:PYTHONPATH = (Get-Location).Path
py -3.11 tools\calibrate_z_press.py
```

终端会打印：

```
>>> 本机 HTTP 服务：http://192.168.x.x:8766/
>>> 在 iPhone Safari 打开 → 分享 → 添加到主屏幕
>>> 从主屏「标定」图标进入（standalone 全屏）
```

记下这个 IP（例如 `192.168.3.10`）。**PC 和 iPhone 必须在同一局域网。**

### 1.2 iPhone 上操作

1. Safari 地址栏输入 `http://192.168.3.10:8766/`
2. 页面显示"等待第一个点…"或靶心圆圈 → 说明连上了
3. 点底部**分享**按钮（方框 + 向上箭头）
4. 下滑找到**"添加到主屏幕"** → 右上角**添加**
5. 回到手机主屏，会多出一个图标
6. **从主屏那个图标进入**（不是从 Safari 进！）

### 1.3 验证是否真的 standalone

进入后看屏幕顶部：**没有 Safari 地址栏** = 对了。
如果还能看到地址栏，说明没加对，重做 1.2。

## 2. 跑 z_press 标定（**必须先做**）

在 1.1 那个已启动的终端里按 **Enter** 开始扫描，或者重新跑：

```powershell
py -3.11 tools\calibrate_z_press.py --up-float 0.4
```

### 它会做什么

```
z=5.0  未触发
z=5.1  未触发
...
z=5.6  触发 ✓
✅ min_z=5.600 + 加深 0.40 → z_press=6.000（硬顶 6.200）
✅ 已写入 config/hardware.json
```

> ⛔ **Z 越大 = 压得越深，硬上限 6.2，超过会点碎屏幕**（用户 2026-09-09 明确）。
> 历史记录里出现过 `min_z=6.300 + 上浮 1.5 = z_press=7.800`，**该值已废弃**：
> 6.3 本身已越过 6.2 硬顶，7.8 更是直接怼屏。若实测 min_z ≥ 6.2，
> 说明笔尖/手机位置偏高，**必须先调整物理位置**，而不是靠加大 Z 去够。

### 参数说明

| 参数 | 默认 | 说明 |
|---|---|---|
| `--start` | 5.0 | 起始 z（离屏最远，浅） |
| `--max` | **6.2** | 最深 z = **硬顶**，超限拒绝执行（旧值 8.0 已废弃） |
| `--step` | 0.1 | 每档加深多少 |
| `--up-float` | **0.4** | 加深量，**安全区间 [0, 0.6]**（旧规范 1~3mm 在 6.2 硬顶下放不下） |

### ⚠️ 失败排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 扫到 8.0 还没触发 | ① 页面没真全屏 ② 触点落在空白区 ③ 机械臂离屏太远 | 确认 1.3；把 `--start` 调低到 4.5 |
| 一上来 z=5.0 就触发 | 起始值已经压到了 | `--start` 调低 |
| `机械臂 open 失败` | COM4 被占 | 重做 0.1 |
| `up_float 必须在 [1, 3]` | 参数超范围 | 改成 1~3 之间的值 |

## 3. 跑机械臂映射标定（**核心**）

```powershell
py -3.11 tools\calibrate_screen_arm.py --grid 8 --z-press 6.0 --max-error-pt 3.0
```

> `--z-press` 用**上一步写回的值**（读 `config/hardware.json` 的 `calibration.z_press`）。

### 它会做什么

```
==== 第 1 轮：校准（64 个靶点）====
[1/64] u,v=(0.060,0.060) arm=(13.60,27.80) touch=(22.0,48.0)
[2/64] u,v=(0.060,0.194) arm=(13.60,45.20) touch=(23.0,157.0)
...
拟合完成：ax=[...] ay=[...]
==== 第 2 轮：验收（10 个点，只测不纠偏）====
验收误差：mean=1.82pt max=2.94pt（阈值 3.0pt）
✅ 已写入 config/hardware.json
```

**机械臂会自己一格一格戳 64 个点**，每点约 1.5~2 秒，全程约 2~3 分钟。
你只需要看着手机屏幕上的靶心被戳中即可，**不用手动碰手机**。

### 参数说明

| 参数 | 默认 | 说明 |
|---|---|---|
| `--grid` | 8 | 网格 N×N，8 = 64 点。想更快用 6（36 点），想更准用 10 |
| `--z-press` | 6.5 | **必须改成第 2 步标定出来的值** |
| `--max-error-pt` | 3.0 | 验收阈值，超了**不写入** |
| `--margin` | 0.06 | 网格距屏幕边缘留白比例（避开边框） |
| `--verify-only` | — | 只跑验收轮，不重新拟合（用已有模型复检） |

### ⚠️ 失败排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `有效样本不足（X/64）` | 大部分点没触发触摸 | ① 重做 1.3 确认全屏 ② 加大 `--z-press` ③ 检查手机是否息屏 |
| `❌ 误差超阈值，不写入配置` | 精度不够 | 看终端给的三种原因提示，逐个排除后重跑 |
| `验收轮 10 点全部超时` | 同上 | 同上 |
| 机械臂戳偏得很规律（都往一个方向偏） | 机械臂间隙 / 回差 | 检查支架松动；考虑单向趋近 |
| 某个角系统性偏 | 支架松动或屏幕不平 | 终端会打印"最差点"，看是哪个角 |

## 4. 重采模板（35 个，逐个来）

### 4.1 单个模板怎么采

```powershell
py -3.11 tools\capture_template.py --name 02_source_red --x 230 --y 525 --w 56 --h 28 --kind icon --purpose "列表页红色全国货源Tab"
```

### 4.2 坐标从哪来

ROI 是**逻辑点坐标**（iPhone X = 375×812）。三个来源：

1. **从源项目基准换算**：全国货源 Tab 实际帧基准 `(243, 533)` 是 480×640 帧像素空间
   → 换算到 375×812：`243/480*375 ≈ 190`，`533/640*812 ≈ 676`
2. **从截图量**：先存一张截图，用看图工具量
3. **用 `--dry-run` 试**：不写文件，先看裁出来的尺寸对不对

```powershell
py -3.11 tools\capture_template.py --dry-run --name test --x 190 --y 660 --w 56 --h 28
```

### 4.3 推荐采集顺序（跟着业务流程走）

| 序 | 页面 | 模板 | 说明 |
|---|---|---|---|
| 1 | 桌面 | `desktop_ymm_icon` | 运满满 App 图标 |
| 2 | 列表页 | `02_source_red` / `02_source_white` | 红/白全国货源 Tab |
| 3 | 列表页 | `05_back_to_top` | 返回顶部 |
| 4 | 列表页 | `02_tingdan_off` / `02_tingdan_on` | 听单开关 |
| 5 | 详情页 | `04_detail_back` / `04_detail_share` | 返回 + 分享（**必须同时命中**才判详情页） |
| 6 | 弹窗 | `99_dialog_close_x` 等 | 关闭图标 |
| 7 | 筛选页 | 清空筛选 / 确认 | 红确认可点，浅红不可点 |

> ⚠️ **`04_detail_back` 历史坑**：源项目里它的 `purpose` 写"左上返回箭头"，
> **实际图像是「举报+分享」组合图**（在画面右侧），靠 `锚点中心 −267px` 才落到真箭头。
> 重采时**直接单独采返回箭头本身**，别再采组合图。

### 4.4 输出

- 图片：`data/templates/_new/02_source_red.png`
- 注册：自动写进 `config/templates.json`，ROI 按逻辑点归一化

## 5. 跑模板得分基线（定阈值）

```powershell
py -3.11 tools\template_baseline.py --frames 30
```

### 输出示例

```
模板                          p50    p05    min    阈值     余量 状态
02_source_red              0.982  0.971  0.963   0.880  +0.083 ✅
04_detail_back             0.895  0.876  0.867   0.880  -0.013 ❌
```

### 怎么读

| 状态 | 含义 | 处理 |
|---|---|---|
| ✅ 余量 ≥0.04 | 安全 | 保持 0.88 |
| ⚠️ 0 ≤ 余量 <0.04 | 卡线 | 记录证据后个案下调 |
| ❌ 余量 <0 | **判不出来** | 必须下调阈值或重采模板 |

> 这就是源项目踩过的坑：`detail_back` 实测 0.867、阈值 0.88 → 详情页永远判不成
> → 返回退化成右滑手势。**基线跑完谁卡线一目了然，不用猜。**

基线写入 `docs/_probe/template_baseline.json`。
