## 3. 坐标空间适配（关键）

### 3.1 改尺寸默认值即可让归一化 ROI 全部复用
把以下配置从 `480×640` 改为 `375×812`（新项目 `config_store.logical_size` 已是 `(375,812)`）：

- `vision.capture.fast_size = (375, 812)`
- `vision.capture.capture_resolution = (375, 812)`
- `calibration.screen_roi = (0, 0, 375, 812)`
- `calibration.screen_roi_ratio = (0, 0, 1, 1)`
- `calibration.roi_calib_size = (375, 812)`

机械臂映射链路 `pixel_to_arm(px, py)`（`arm.py`）原样保留——它已由 `logical_size` 推导 `screen_roi`，改尺寸即自动适配。**这是相对摄像头方案最大的简化**。

### 3.2 归一化 ROI（0..1）直接复用
`city_picker` 的 `GRID_ROI_*`、`detail` 的 `price.roi`/`distance_km.roi`、`handlers` 的 `panel_tab_roi` 等都是归一化，比例一致，保留。

### 3.3 绝对像素常量必须按 375×812 重标定（待真机）
这些是写死在 fast 帧 px 的常量，**用户采集模板后结合真机重测**：

| 位置 | 常量 | 说明 |
|---|---|---|
| `city_picker.py:318` | `row_tol=28` | 同行动别阈值 |
| `city_picker.py:394-398` | `dx=-122`(origin)/`-64`(dest) | 入口定位像素偏移 |
| `detail.py:633` | `offset_from_center=136` | 弹窗×相对标题中心偏移 |
| `scanner.py:113-115` | `min_height=90 / max_height=420 / first_card_min_y=90` | 卡片几何 |
| `actions.py:500-512` | `press_back` 偏移 `[-250,0]`/`[-64,0]` | 返回键锚点像素偏移 |
| 各处 | `dy` / `confirm_dy=3` | 点击纵向微调 |

换算比例：x 方向 ×(375/480)=0.781，y 方向 ×(812/640)=1.269。先按此预填，真机微调。

## 4. 接口差异与对齐方案（需逐文件核对）

| 差异点 | 现状 | 对齐方案 |
|---|---|---|
| `arm.set_frame_size(w,h)` | 新 `arm.py` **无此方法**（screen_roi 由 logical_size 直接算） | 给新 `arm.py` 加兼容 `set_frame_size`（仅记录，screen_roi 仍用 logical_size）；或改 `flow/task.py:331` 去掉该调用 |
| `matcher.find` 实参 | 源 flow 调用形式需核对（字符串模板名 vs `TemplateSpec`） | 新 `matcher.find(frame, spec, search_roi, threshold)` 收 `TemplateSpec`；若源传名，flow 改为先 `store.template(name)` 取 spec 再传 |
| `page_state` 导出类 | 新 `page_state.py` 已确认有 `ScreenState`（九态）；`PageDetector`/`PageResult` 需核对导出 | 缺失则在 `page_state.py` 补别名导出，或改 flow import |
| `FrameSource` 实现 | 新 `frame_source.py` 需含 `imouse` 分支 | 确保 `create_frame_source()` 返回 `ImouseFrameSource`，产 `FrameSet(raw=fast=375×812)` |
| `ocr_scale` / raw↔fast 换算 | iMouse 下 `raw==fast`、比例=1 | `actions.ocr_scale` 自然得 1，无需改；`city_picker` 的 raw 换算分支自动失效（安全） |
