# 页面状态判定与流畅滑动经验（踩坑沉淀）

> 来源：用户 2026-09-09 口述的「之前项目走过的路」总结 + 旧项目 `robot_order_picker_new` 已固化代码。
> 用途：imouse 项目目前**只有标定/配置/采模板工具，运行时状态机（page_state）尚未实现**。
> 本文是未来写状态机与滑动动作时的唯一权威依据，**改状态机逻辑前先读本文**。

---

## 一、订单列表页判定

判断是否处于「订单列表页（红色全国货源列表）」：

- 命中 `source_red`（底部红色全国货源 Tab） **或** `back_to_top`（红色返回顶部按钮）
  → 说明在列表页
- 两者都不命中 → 不在列表页（可能在详情页 / 聊天页 / 筛选页 / 未知页）

> 注意 `source_white`（白色全国货源）命中只说明「在首页非列表态（如新货 Tab）」，需点成红色才进列表。

## 二、列表页「顶部是否隐藏」判定

进入列表页后，**顶部区域（听单开关、找货记录、司机课堂）可能处于隐藏状态**（被滑上去）。

判据：在列表页里

- 若 `听单开` / `听单关` **都找不到**，且 `找货记录` / `司机课堂` 也找不到
  → 顶部隐藏，需要展开（见第三节）
- 能找到其中任一 → 顶部已展开

> 因此 `听单开` / `听单关` / `找货记录` / `司机课堂` 这四个模板，本质就是「顶部已展开」的判据。
> **采集这四个模板的前提：必须先在「列表页 + 顶部已展开」状态下截帧**（否则截不到）。

## 三、展开顶部（下滑）的前置：底部状态机

**滑动之前必须先确认底部是 `source_red`（红色全国货源图标）**。不是红色则要分情况处理：

| 底部当前状态 | 处理 |
|---|---|
| 红色全国货源 `source_red` | 直接操作，进行下滑 |
| 白色全国货源 `source_white` | **先点它** → 变红 → 再操作 |
| 红色返回顶部 `back_to_top` | **先点它** → 变回红色全国货源 → 再操作 |

确认是红色全国货源后，再进行下滑操作。

**下滑动作本身**：在屏幕**中间区域**（x ≈ 0.42~0.58 屏宽）**短滑**下滑（滑动长度不要太长，短滑即可）。
下滑后顶部隐藏区显示出来，此时就能看到 `找货记录` / `司机课堂` / `听单开` / `听单关`。

## 四、流畅滑动实现规范（参考旧项目，禁止卡顿式）

用户明确要求：滑动**不要做成卡顿式**，要**流畅的滑动**、**短滑**。

旧项目 `robot_order_picker_new` 已有「已固化」的流畅滑动实现，imouse 项目移植时**照抄思路，不要另起炉灶写 `move()+sleep` 卡顿式**：

### 4.1 底层：连续轨迹下发

- `core/devices/arm.py` `move_continuous`（行 271-282）：滑动专用，下发 move 指令且 **delay≈0**，让机械臂连续跟随轨迹点平滑划过，避免逐点停顿的「搓屏」感。
- `core/devices/arm.py` 构造函数（行 79-82）：用 **keep-alive `requests.Session`** 复用一条 TCP 连接。滑动时每秒下发几十条轨迹点，逐条新建连接的手持抖动（几 ms~几十 ms）会直接变成「一顿一顿」——复用连接后 RTT 稳定，轨迹才跟得上。

### 4.2 高层：swipe 封装

- `core/flow/actions.py` `swipe`（行 336-413）：按下 → 连续 `move_continuous` 轨迹 → 抬起。

关键实现要点（移植时务必保留）：

1. **轨迹形状**：三次贝塞尔曲线 `_cubic_bezier`（行 33-36），控制点带随机偏移，避免每次一条直线（机械式特征）。
2. **绝对时间轴 pacing**（行 388-401）：每步按「应当到达的时刻」补 `sleep`，**不是每步固定 sleep**。某一步 HTTP 慢了，下一步自动少睡 → 总时长与点位间隔都稳，不会被 RTT 抖动越拖越长（旧实现总时长能翻好几倍）。
3. **抖动单位**：每步 ±**0.15 机械臂单位**（行 371, 396-397）。**绝不能用像素级 6px 抖动**——旧版每步加 6px，换算到机械臂坐标约 0.8 单位，远大于人体自然抖动，是「一卡一卡」的根因。
4. **步间隔**：约 **16ms** 一个点（行 369），下发次数减半、节奏更稳。
5. **按下先稳** `press_settle≈60ms`（行 372, 379-382）：笔尖刚接触就开滑会打滑不跟手（表现「先卡一下再动」）。
6. **抬手后等惯性** `release_settle≈120ms`（行 373, 403-405）：否则下一帧拍到滚动中途的糊画面。
7. **时长受控**：`duration_ms_range` 默认 [600,1000]（慢拖），消除 iOS 惯性翻页；从区间随机取再叠 ±15% 抖动。

### 4.3 短滑幅度

- `swipe_down`（行 440-450）：默认 `down_distance_ratio = 0.25`（下滑 0.25 屏高）—— 正是用户说的「短滑」。
- `swipe_up`（行 415-438）：上滑翻页用 `up_distance_ratio_range=[0.3,0.5]` × `amplitude_multiplier=[1.7,2.3]`（均值约 2 倍屏高，用户实测认可的翻页幅度）。
- 起点 x 取屏宽 0.42~0.58（中间区域），符合用户「屏幕中间区域下滑」。

### 4.4 imouse 项目现状与待办

- imouse 的 `imouse_client.py` **只有截图/找色/键盘**，无滑动（符合边界：iMouse 只「看屏」，滑动由机械臂执行）。
- imouse 的 `core/devices`（对应 `calib_common.py` 的 `ArmClient`）目前只有 `move/press/release/reset`，**没有 swipe 封装**。
- **待办**：写 imouse 版 `ActionKit.swipe`（坐标走 `calib_common.predict` 像素→机械臂映射），严格按本文 4.1~4.3 规范实现流畅短滑。

## 五、采模板时如何用本文

| 模板 | 所在位置 | 采集前置状态 |
|---|---|---|
| `detail_report` 详情页举报 | 货源**详情页**（右上/底部举报入口） | 进入任意货源详情页即可，**不依赖顶部展开** |
| `goods_history_record` 找货记录 | 列表页**顶部隐藏区** | 列表页 + 顶部已展开（按第三节下滑） |
| `driver_school` 司机课堂 | 列表页**顶部隐藏区** | 列表页 + 顶部已展开（按第三节下滑） |
| `tingdan_on` / `tingdan_off`（已有） | 列表页顶部 | 同上，顶部已展开 |
