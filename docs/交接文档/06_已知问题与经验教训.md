## A. 标定 / 坐标类

### A1. `calibrate_xy.py` 拟合 bug —— 反复"标完又错"的元凶
- **现象**：`x_scale` 在 `0.78 ↔ 0.98 ↔ 1.006` 之间来回跳，点哪都不准
- **根因**：`_fit()`（230-250）把 base 空间与机械臂坐标空间混用，
  **只有 `scale=1.0/offset=0.0` 时结果才正确**
- **规避**：重跑 XY 前必须先跑 `calibrate_screen_roi.py`（自动重置 scale/offset）
- **待办**：该 bug 未修；建议加防护（非 1.0 起点时拒绝写回或自动换算）

### A2. `arm_range` 失配 → 病态 scale
- **现象**：`x_scale=0.76651`、`0.78541`（正常应 ≈1.0）
- **根因**：`arm_range` 由 `screen_roi` 按比例**继承**（非实测），误差累积
- **解法**：把已验证的 scale/offset **等价折叠进 arm_range**（纯线性，数学等价）
  - `new_x0 = x0*s + o`，`new_x1 = x1*s + o`，scale=1.0，offset=0.0
  - 2026-09-08 实操：跨度 79.56mm → 62.49mm（≈ iPhone X 屏宽 61.8mm），复算误差 ≤0.3mm
- **健康判据**：scale ±0.05 内、offset ±3mm 内

### A3. 页面识别回归（2026-09-08 事故）
- **现象**：详情页被判成 `order_list`；详情页返回变成**右滑手势**
- **根因**：`thresholds.detail.back/share` 从 **0.86 被抬到 0.88**，
  而 `detail_back` 实测得分只有 **0.867**（卡在 0.88 线下）
  → 双按钮 AND 判定失败 → 判不出详情页 → `press_back` 锚点失败 → 退化手势
- **处置**：降回 **0.82**（余量约 0.04）
- **教训**：**"铁律 0.88 一刀切"是有害的**；阈值必须按每个模板的实测分布定

### A4. 机械臂 8082 掉线被误报成"箭头检测失败"
- **现象**：日志 `返回箭头检测失败，改手势: HTTPConnectionPool(host='127.0.0.1', port=8082)... WinError 10061`
- **根因**：`press_back()` 用一个 `except Exception` 包住整段，
  **通信异常也被报成"箭头检测失败"**
- **教训**：**排障要看异常原文**，不要只看中文提示
- 8082 掉线多为瞬时（服务重启期间），重跑通常恢复

### A5. 采集链路横向拉伸 ×1.333
- 采集 720×1280 → 目标 960×1280，**宽度被拉 1.333 倍**
- 后果：屏幕 ROI 比例 **1.595** 而非 iPhone X 的 2.165
- **教训**：标定时看到"h/w 应接近 2.17"的提示**不要去凑**，这个链路下 1.6 才是对的

### A6. 标定期间移动手机 = 前功尽弃
- `z_press` 标定需要手机停在**特定页面并点真实控件**，切页极易挪动设备
- **规避**：切页用手指垂直轻点，不要推；最好用胶带/重物固定
- 每次标定前/后可对比 `screen_roi` 自动检测结果，确认没位移

## B. 模板 / 识别类

### B1. 模板命名与实际内容不符
- `detail_back` 的 `purpose` 写"左上返回箭头"，
  **实际图像是「举报 + 分享」组合**（在画面右侧）
- **教训**：改模板前**先打开图看一眼**，别信 purpose

### B2. "锚点 + 大偏移"极脆
- `detail_back` 锚点 (379,98)，`offset=-267` 才落到箭头 (112,103)
- 锚点抖 2px 或 UI 微调，落点就漂
- **方向**：优先直接定位目标本身；必须用时锚点要靠近目标

### B3. 阈值卡线
- 得分 0.867 vs 阈值 0.86，余量仅 **0.007** → 光线一变就掉线
- **要求**：余量 ≥0.04

### B4. 素材冗余
- **17 个重复素材**、**20+ 个未标注时间戳采集**（`_new/采集_*.png`）
- 9 个模板 `roi: null`（全帧搜索）→ 误报高、耗时高

### B5. `tap_offsets.json` 无人消费
- `tools/live_click.py` 会写 `config/calib/<slug>/tap_offsets.json`，
  但 `core/`、`gui/` **零处引用** → 生产不读取
- 曾误以为它会影响点击；不要在上面浪费时间

## C. 打包 / 部署类

### C1. VC++ DLL 版本：要 **14.50**，不是降级
- `build.spec` 注释明确：Qt 自带 **v14.26 旧版**会让 onnxruntime 初始化失败
  （报"DLL 初始化例程失败"或"找不到序数 380"）
- `build.spec` 已用 `_BAD_VC` 过滤剔除 Qt 旧版，并显式打包 System32 的 MSVCP140_1
- **打包后 4 个 DLL 都应是 `14.50.35719.0`**
- ⚠️ 曾误判为"14.50 太新，应降级 14.34" → **方向反了**，别再犯

### C2. `uac_admin` 必须为 False
- 带管理员 manifest 的打包进程里，`onnxruntime_pybind11_state.pyd` 会报
  "DLL 初始化例程失败"
- 提权改由快捷方式 / 启动脚本的"以管理员身份运行"承担

### C3. onnxruntime 必须在 PyQt5 之前 import
- `gui/app.py:45-52` 明确说明：顺序反了会 DLL 冲突

### C4. 打包依赖容易漏
- `rapidocr_onnxruntime` 的 onnx 模型不在 .py 中 import，必须 `collect_data_files` 显式收
- `six` 曾漏打导致 rapidocr 整体导入失败 → OCR 全降级
- `MSVCP140_1.dll` 是 onnxruntime 的静默依赖，必须显式 binaries

### C5. 改了源码 ≠ 生产生效
- 改源码 → 必须重新 `PyInstaller build.spec` 并部署
- 只改配置 → 同步进 `dist_v5/RobotPicker/_internal/config/` 即可

### C6. 部署时文件被占用
- 运行中替换会报 `WinError 32 另一个程序正在使用此文件`
- **流程**：停 JxbService → 结束 `RobotPicker.exe` → 部署 → 重启服务
- 注意：服务停了 GUI 进程可能仍在；且有时会自动被重新拉起，需复查

## D. 流程 / 逻辑类

### D1. 默认不真抢单
- `runtime.dry_run = true`、`review_mode = true`
- **默认跑起来只会停在详情页等人工**——这是安全设计，不是 bug

### D2. 距离只能在详情页拿到
- 列表卡片上的距离是**"距装货点"**，不是运输距离
- 而 `单价 = 价格 ÷ 距离` → **每个候选都必须进详情**
- 这是提速的最大障碍（详情页 7~9s × 3~5 个候选）

### D3. 货物可能写在「货主要求」里
- 只按"货物"标签抽会漏 → 被误判为"需要滑第二屏"
- 应**双路抽取**：货物标签行 + 货主要求内容

### D4. 详情页 OCR 重复调用
- 一个详情页 2~3 次全屏 OCR（第一屏 / 第二屏 / 弹窗判据）
- 代码注释自陈："实测详情读字段中位 4082ms，一半是浪费"
- **注意**：`ocr(roi=...)` 会绕过 `ActionKit` 的帧级缓存，别这么调

### D5. 听单判定走颜色判据
- 不在 `thresholds.tingdan`，而在 `hardware.calibration.tingdan`

## E. 操作 / 工具类

### E1. 交互式工具的控制台输入
- `calibrate_screen_roi.py` / `calibrate_xy.py` / `calibrate_press.py` 都有 `input()` 提示
- **AI 自动化环境无法提供 stdin** → 会 `EOFError` 崩溃
- 只能由人工在自己的 PowerShell 里跑；GUI 窗口部分可以自动化

### E2. PowerShell 命令里的 `$` 会被吞
- `execute_command` 走 PowerShell 时 `$_` / `$p` 等变量会被吃掉
- **解法**：写成 `.ps1` 文件再 `-File` 执行

### E3. `&` 在 PowerShell 中不可用
- 用 `;` 分隔命令

### E4. py -c 里的格式说明符（`:<22`）会被破坏
- 复杂 f-string 建议写成脚本文件
