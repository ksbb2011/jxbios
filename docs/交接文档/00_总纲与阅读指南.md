## 1. 这个项目是干什么的

**运满满抢单机器人**——用**机械臂**代替人手，操作一台**真实 iPhone**，在「运满满」App 里
自动**扫码找货 → 判断是否符合条件 → 抢单**。

关键点（决定了整个系统的复杂度）：

| 约束 | 含义 |
|---|---|
| **操作对象是真手机** | 不能装插件、不能 hook、不能改 App |
| **感知靠外接摄像头** | 摄像头从外部拍手机屏幕（不是截图），有透视/畸变/反光 |
| **执行靠机械臂** | 通过 HTTP 控制的机械臂带动电容笔点击/滑动 |
| **必须像人** | 有反风控：随机停顿、贝塞尔滑动、抖动、行为画像 |

> ⚠️ 这是**保底版本**：不依赖任何投屏/截图工具。
> 官方一旦限制投屏，系统必须能回到"纯摄像头 + 机械臂"模式继续跑。

## 3. 三十秒速览

```
摄像头(USB) ──拍──> 手机屏幕 ──> 480×640 快帧 ──> 模板匹配 + 页面判定(11 态)
                    │                                    │
                    └────> 960×1280 原始帧 ──> OCR ───────┤
                                                          ↓
                                                   状态机分发 → handler
                                                          ↓
                                              ActionKit（点击/滑动/OCR）
                                                          ↓
                                            RobotArm ──HTTP:8082──> 机械臂 ──> 戳手机屏幕
```

**一次抢单**：桌面点图标 → 进列表 → 扫卡片（OCR + 规则初筛）→ 点进详情 →
OCR 读字段 → 算单价 → 合格则抢（或暂停等人工）→ 返回列表 → 继续。

## 4. 当前运行形态

| 项 | 值 |
|---|---|
| 手机 | iPhone X（`hardware.device.model`） |
| 机械臂 | COM4，HTTP 服务 `http://127.0.0.1:8082/MyWcfService/getstring` |
| 摄像头 | index 0，采集 1280×960 → 旋转 → 目标 960×1280，快帧 480×640 |
| 服务 | `JxbService`（**普通进程不是 Windows 服务**，但用 `Restart-Service` 管理） |
| 界面 | PyQt5 GUI（`gui/app.py`，标题「运满满抢单机器人 V2.8」） |
| 打包 | PyInstaller `build.spec` → `dist/RobotPicker/` |
| 生产包 | `dist_v5/RobotPicker/RobotPicker.exe`（旧包备份 `dist_v5/RobotPicker_bak_*`） |

## 5. 默认配置下的行为（重要！不知道会以为程序坏了）

`config/runtime.json`：

| 开关 | 当前值 | 含义 |
|---|---|---|
| `dry_run` | **true** | **试运行**：判定与记录照做，但**不会真的点「立即抢单」** |
| `review_mode` | **true** | **审核模式**：候选合格时**暂停在详情页等人工确认** |
| `no_pause_test` | false | 与上面配合；为 true 时不暂停，sleep 5s 后离开 |

> 也就是说：**默认跑起来不会真抢单，只会停在详情页等你点「继续找单」**。
> 这是刻意的安全设计，不是 bug。

## 6. 给新 AGENT 的开场词（可直接复制粘贴）

> 你在接手一个叫「运满满抢单机器人」的项目（Python 3.11 + PyQt5 + OpenCV + RapidOCR + 机械臂）。
> 它用**机械臂**操作一台**真实 iPhone X**，靠**外接 USB 摄像头**看屏幕（**不是截图、不投屏**），
> 在「运满满」App 里自动找货、判断、抢单。这是**保底版本**，不允许依赖任何投屏工具。
>
> 请先按顺序读完 `docs/交接文档/` 下的 00~07 号文档，它们完整描述了：
> 业务流程与 11 个页面状态机、架构与模块职责、**像素→机械臂的坐标链路与三步标定**、
> 模板与阈值体系、9 个配置文件、`06` 号文档里**历史真实踩过的坑**（务必逐条看）、
> 以及基于 iMouse 投屏的新架构改造建议。
>
> 另外 `docs/方案_*.md` 三份是已定稿但**尚未实施**的重构方案（标定 / 提速 / 模板可靠性），
> 三者的依赖关系是：**标定方案是另外两个的前置**。
>
> 在动手改任何东西之前，请先复述你对项目的理解，并说明你打算改动的范围，等我确认。

## 7. 交接时的几个提醒

1. **不要动 `dist_v5/RobotPicker_bak_*`** —— 那是可回退的旧生产包。
2. **改配置前先备份** —— 项目有 `犯错记录.md` 传统，踩坑要记。
3. **坐标相关的改动要格外小心** —— 见 `03` 和 `06`，本项目 80% 的故障都出在这里。
4. **打包不等于生效** —— 改了源码要重新 `PyInstaller build.spec`；改了 `_internal/config` 才对生产包立即生效。
5. **改动要能回退** —— 每个新功能做成可开关（配置项），不达标立即关。
