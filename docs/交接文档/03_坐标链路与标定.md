# 03 · 坐标链路与标定（本项目最大的坑）

> **本项目的绝大多数故障都出在这一块。** 改动坐标相关代码前，请把本文档和
> `06_已知问题与经验教训.md` 一起读完。

---

## 1. 坐标链路（5 段参数，强耦合）

```
帧像素(480×640 fast)
   ↓ ① screen_roi 归一化 (u,v)
   ↓ ② arm_range 线性映射
   ↓ ③ x/y scale + offset 修正
   ↓ ④ top_y_adjust 顶部透视修正
   ↓ ⑤ z_compensation 边角分区补偿
机械臂坐标 (ax, ay)
```

实现：`core/devices/arm.py:354-393 pixel_to_arm()`

```python
u = clamp((px - left) / width, 0, 1)
v = clamp((py - top)  / height, 0, 1)
ax = x0 + u * (x1 - x0)          # arm_range.x
ay = y0 + v * (y1 - y0)          # arm_range.y
ax = ax * x_scale + x_offset
ay = ay * y_scale + y_offset
if top_y_adjust: ay -= top_y_adjust * (1.0 - v)
# z_compensation：u>=right_ratio / v>=bottom_ratio 时叠加 right/bottom/corner
```

逆向：`arm_to_pixel()`（395-404，数值求逆，调试可视化用）。

### 参数现状（2026-09-08 标定后）

| 参数 | 值 |
|---|---|
| `screen_roi` | `[85, 63, 406, 575]` |
| `arm_range` | `x[9.93, 73.2]`（跨度 63.27mm）`y[16.62, 154.62]` |
| `x_scale / x_offset` | `1.00527 / -0.657` |
| `y_scale / y_offset` | `0.99989 / -0.360` |
| `z_press` | `6.5` |
| `z_compensation` | `right 0.15 / bottom 0.15 / corner 0.3`（mm） |
| `top_y_adjust` | `0.0` |

### ⚠️ 采集链路还有一次横向拉伸

```
采集 1280×960 → 旋转 720×1280 → 目标 960×1280   ← 宽度 720 被拉成 960（×1.333）
```

后果：屏幕 ROI 比例是 **1.595**，而 iPhone X 真实比例是 **2.165**
（2.165 ÷ 1.333 ≈ 1.62，吻合）。
→ **所有图标模板在画面里都是"横着的"**，加剧图色匹配不准。
→ 标定时看到 `高/宽比 1.60（iPhone X 约 2.17）`的提示，**不要去凑 2.17**，1.6 才是这个链路下的正确值。

## 2. 三步标定（顺序不可颠倒）

| 步 | 工具 | 做什么 | 写回 |
|---|---|---|---|
| 1 | `tools/calibrate_screen_roi.py` | 框出屏幕四角 | `screen_roi` + 按比例同步 `arm_range`，**并把 scale/offset 重置为 1.0/0.0** |
| 2 | `tools/calibrate_xy.py` | 机械臂真压四角，人工点笔尖 | `x_scale/x_offset/y_scale/y_offset` |
| 3 | `tools/calibrate_press.py` | 逐档下压找触发点 | `z_press` |

命令：
```
py -3.11 tools/calibrate_screen_roi.py
py -3.11 tools/calibrate_xy.py
py -3.11 tools/calibrate_press.py --scene list_tab --hold 2
```
（也可用根目录的 `标定屏幕.bat` / `标定XY.bat` / `标定z_press.bat`）

### 🔴 致命陷阱：`calibrate_xy.py` 的拟合 bug

`_fit()`（`tools/calibrate_xy.py:230-250`）把 **base 空间** 与 **机械臂坐标空间** 混用：

```python
p1, p0 = lstsq([base, 1], actual_pixel)     # 实测：pixel = p1*base + p0
want_ax = (target_pixel - p0) / p1          # 这是【base 值】，不是机械臂坐标！
scale, offset = lstsq([base, 1], want_ax)   # ✗ 直接令 base*s+o = want_ax
```

正确应为 `arm_want = want_ax * S_old + O_old` 再拟合。

**后果**：**只有当运行前 `scale=1.0 / offset=0.0` 时，拟合结果才正确。**
否则它会把"增量修正"当成"绝对值"写回，**抹掉已有修正**。

典型表现：反复标定，`x_scale` 在 `0.78 ↔ 0.98 ↔ 1.006` 之间来回跳，
点哪都不准——**用户曾为此崩溃多次**。

**规避**：重跑 XY 前，务必先跑一次 `calibrate_screen_roi.py`（它会自动重置 scale/offset）。

## 3. `arm_range` 为什么必须"折叠"（重要经验）

**问题**：`arm_range` 不是实测的，而是由 `screen_roi` **按比例继承**的，
误差代代相传，最后只能靠 `scale` 硬凑 → 出现 `x_scale=0.76651 / 0.78541` 这类病态值。

**解法（已验证）**：因为映射是**纯线性**的，
```
arm = (x0 + u*(x1-x0)) * s + o
    = (x0*s + o) + u * ((x1-x0)*s)
```
所以可以把已验证正确的 `scale/offset` **等价折叠进 `arm_range`**：
```
new_x0 = x0*s + o
new_x1 = x1*s + o
scale = 1.0, offset = 0.0
```

**2026-09-08 实操**：把 `x_scale=0.78541 / x_offset=9.054` 折叠进
`arm_range.x`，跨度从 79.56mm → **62.49mm**（≈ iPhone X 屏宽 61.8mm，物理上合理），
scale 回到 1.0。折叠后复算四个点，与实测机械臂坐标差 **≤0.3mm**。

**健康判据**：`scale` 应 ≈1.0（±0.05）、`offset` 应在 ±3mm 内。
出现 0.78 之类，说明 `arm_range` 与 ROI 失配。

## 4. 精度现状与瓶颈

| 位置 | 误差 |
|---|---|
| 四点拟合残差（内部点 0.2/0.8, 0.15/0.85） | **0.08mm**（很小） |
| live_click 实测落点 | 右上 **3.1px** → 左下 **5.5px** → 右下 **9.4px** |

→ **越靠边角误差越大**。原因：仿射（线性）映射无法表达透视与镜头径向畸变，
只能靠 `z_compensation` 打分区补丁；**补丁绑定当前姿态，设备一动就失效**。

---

## 5. 下压深度 `z_press`

- 由 `calibrate_press.py` 实测：从 `--start-z`(5.0) 逐档加深，手机有反应即停
- 写回 `min_z + 上浮值`（默认 0.3，范围 0.1~0.5）
- 当前 **6.5**（2026-09-08：min_z=6.00 + 用户要求再加 0.2）
- ⚠️ 6.5 已比接触点深 0.5mm，是推荐区间上限；再深有顶屏风险

> 标定 z_press 需要手机停在**特定页面并点真实控件**（点空白区无法判断是否压到），
> 切页时**极易挪动设备导致前功尽弃**——这是标定流程最脆弱的一环。

## 6. 根因总结与根治方向

| 根因 | 说明 |
|---|---|
| 链路过长、5 段参数强耦合 | 改一个动全身 |
| `arm_range` 继承而非实测 | 误差累积 |
| 仿射无法表达透视 | 边角残差 → 死补丁 |
| 补丁绑定姿态 | 设备一动就失效 |
| `calibrate_xy` 拟合 bug | 非 1.0 起点重跑即破坏 |
| 采集链路横向拉伸 ×1.333 | 模板变形 |
| 光线影响 ROI 自动检测 | 同一场景三次给出 1.60/1.63/1.67 |

### 根治方案（已定稿，尚未实施）

**引入"手机屏幕坐标系"作为中间层，两步解耦：**

```
摄像头像素 ──①──> 手机屏幕坐标 ──②──> 机械臂坐标
```

- ① 手机全屏显示已知图案（ArUco 网格）→ 摄像头识别 → 求对应关系（含畸变）
- ② 机械臂点图案上的已知靶点 → 手机上报真实触摸坐标 → 拟合

**收益**：精度 ≤3px（现 9px）、耗时 <2 分钟（现 1~2 小时）、
移动设备后各侧重算 1 分钟、模板一次采集长期有效。

详见 `docs/方案_标定体系重设计.md`。

## 7. 改动坐标相关代码的检查清单

1. ☐ 是否清楚当前 `scale/offset` 是否为 1.0（决定能否直接跑 `calibrate_xy`）
2. ☐ 改动后是否用 `live_click.py` 实测过边角落点
3. ☐ 是否同步到生产包 `dist_v5/RobotPicker/_internal/config/hardware.json`
4. ☐ 是否备份（项目根与生产包各留一份 `.bak_*`）
5. ☐ 是否确认手机在标定期间**没有被移动**
6. ☐ 改了源码是否重新打包（只改配置则不需要）
