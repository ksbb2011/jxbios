# 07 · 新项目改造建议（基于 iMouse 投屏）

> **背景**：新项目将借助 **iMouse（爱鼠）投屏工具的 API** 实现屏幕抓取、图色、OCR。
> 软件逻辑与业务规则**完全不变**，变的只是"感知与操作的手段"。
> 机械臂仍然是执行层。
>
> ⚠️ **本项目（robot_order_picker_new）是保底版本**——官方一旦限制投屏，
> 必须能回到"纯摄像头 + 机械臂"模式。因此当前项目**不能废弃**，
> 新项目结束后还要回来继续优化。

## 2. 投屏带来的核心收益

| 痛点（现在） | 投屏后 |
|---|---|
| 摄像头透视/畸变，边角误差 9px | **无透视**，屏幕坐标天然准确 |
| 光线影响 ROI 检测与匹配 | **不受环境光影响** |
| 采集链路横向拉伸 ×1.333 | 原生分辨率，无拉伸 |
| 模板定义在相机像素空间，设备一动全失效 | 模板定义在**设备屏幕坐标**，与相机无关 |
| OCR 受拍摄模糊影响 | 原生截图，小字更清晰 → 可降 `det_limit_side_len` 反而更快 |
| 三步手工标定 1~2 小时 | 见下 |

## 3. 简化后的坐标问题（**关键，别以为投屏就没坐标问题**）

投屏解决了"**看得准**"（视觉侧），但**没有**解决"**点得准**"（执行侧）：

```
屏幕坐标（已知，投屏直接给）  ──?──>  机械臂坐标（仍需标定）
```

机械臂是物理设备，它与手机屏幕的物理对应关系**依然要标定**。

**建议直接采用当前项目已定稿的方案**（`docs/方案_标定体系重设计.md` 的第 ② 层）：

> 手机全屏显示已知靶点（网页 / App）→ 机械臂去点 → **手机上报真实触摸坐标**
> → 得到 `目标屏幕坐标 ↔ 实际触点` → 拟合双线性模型

这条路与是否投屏**无关**，且投屏后还能更简单：
- 可直接用投屏的截图确认页面状态，不需要摄像头复核
- 触摸坐标可由投屏侧或页面侧上报

**收益**：标定从"三步手工 1~2 小时" → "点几十个已知点，1~2 分钟"，精度 ≤3px。

## 4. 建议的新架构

```
iMouse API
   ├── 屏幕抓取  → 原生分辨率帧（替代 Camera）
   ├── 图色/模板 → 匹配在【设备屏幕坐标】空间（替代 TemplateMatcher 的相机像素空间）
   ├── OCR       → 原生截图，按字段 ROI 裁切（比现在快且准）
   └── （可选）触摸注入 / 坐标上报

        ↓ 与现在相同的状态机 / 规则引擎 / 流程编排

机械臂 HTTP:8082  → 物理点击/滑动（唯一执行层，不变）
```

**关键设计原则**：
1. **坐标空间统一到"设备屏幕坐标"**（如 375×812），所有模板 ROI、点击点都用它
2. **机械臂映射单独标定**（屏幕坐标 → 机械臂），与视觉侧解耦
3. **`core/domain/` 零改动**——业务规则与感知手段无关
4. **保留降级开关**：投屏不可用时能切回摄像头模式（保底）

## 5. 落地建议顺序

| 阶段 | 内容 | 说明 |
|---|---|---|
| 1 | 打通 iMouse 抓屏，替换取帧源 | 先让"看得见"，其余逻辑不动 |
| 2 | 模板与 ROI 迁移到屏幕坐标 | 需按新分辨率重新采集/换算 |
| 3 | OCR 换用原生截图，调 `det_limit_side_len` | 预期更快更准 |
| 4 | 机械臂映射标定（网页/App 上报触摸坐标） | 复用已定稿方案的第 ② 层 |
| 5 | 业务回归：桌面→列表→详情→抢单全链路 | 用 `dry_run + review_mode` 先跑通 |
| 6 | 提速：按行 ROI、消除重复 OCR、按需读第二屏 | 复用 `docs/方案_扫描与OCR提速.md` |

## 6. 风险与注意

| 风险 | 说明 | 应对 |
|---|---|---|
| **官方限制投屏** | 这是最大风险，也是保留保底版本的理由 | 保底项目不能废弃；新项目要能降级 |
| iMouse API 稳定性 | 延迟、断连、版本变更 | 抽象 `FrameSource` 接口（现在已有），便于切换 |
| 投屏延迟 | 可能影响"点完立即复判"的时序 | 复判前多等一帧或加稳定检测 |
| 模板需重采 | 分辨率变了，现有 38 个模板可能不适用 | 可用 `_auto_resample_icons.py` 重采样，或按新分辨率重采 |
| 反风控 | 投屏本身可能被视为风险特征 | 需评估；这也是保底版本存在的意义 |
