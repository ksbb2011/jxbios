# 运满满抢单机器人 —— 打包与交付说明

> 生成时间：2026-09-13　构建方式：PyInstaller 6.22.2 onedir + UAC 管理员清单
> 入口：`gui/app.py`（GUI 主程序，含「启动」按钮）　Python：3.11.2 x64

---

## 1. 一键打包

双击 **`installer\build_exe.bat`**（或命令行执行 `py -3.11 -m PyInstaller installer\build_exe.spec --noconfirm --clean`）。

时间：首次约 2 分钟（实测本机 80 秒，产物 312MB —— 含 GUI 与校准工具两个 exe），之后改代码再打包同样时长。

bat 会依次做 5 件事：

| 步骤 | 做什么 |
|---|---|
| 1 | 检查 PyInstaller，没有就装 |
| 2 | 清理旧的 `build\` 与 `dist\运满满抢单机器人\` |
| 3 | 执行 spec 编译 |
| 4 | 把 `config\`、`data\templates\`、`tools\` 拷到 **exe 同级** |
| 5 | 建空的 `data\{logs,shots,traces,neg_frames}\` + 生成 `启动.bat` |

只想重做第 4~5 步（不重新编译）用：`installer\build_exe.bat nobuild`
（改完 `tools\*.py` 或 `config\` 后刷新产物，10 秒级；会校验两个 exe 都在）

### 四条不能破的约定

1. **`config\` 与 `data\templates\` 必须与 exe 同级**（不是放进 `_internal\`）。
   原因：`core/config_store.py` 的 `_project_root()` 在打包后（`sys.frozen`）取的是
   `Path(sys.executable).parent`。GUI 用 `ConfigStore(strict=True)`，少任何一个
   json 都会「弹窗 + 抛异常」直接起不来。
   （`docs\交接文档\` 里写的 `_internal/config` 是**旧项目**的布局，不要照抄。）
2. **`data\templates\` 是识别资产，不是运行产物** —— 漏了会「识别全废」。
3. **onnxruntime 必须早于 PyQt5 导入**（否则 `DLL 初始化例程失败`）。
   顺序由 `gui/app.py` 模块级代码保证，spec 只做静态收集。改 `gui/app.py` 顶部导入顺序时务必注意。
4. **包里只允许存在一套 VC++ 运行库**（2026-09-13 新增，血泪约定）。
   PyQt5 的 wheel 自带一套**旧版** `MSVCP140.dll` 等放在 `_internal\PyQt5\Qt5\bin\` 下，
   PyQt5 会把该目录加进 DLL 搜索路径；冻结环境启动时它先占坑，随后
   `onnxruntime_pybind11_state.pyd` 就报 `[WinError 1114] 初始化例程失败` → rapidocr 导入失败
   → **OCR 全废 → 页面判态失去依据（不点红色「全国」、不清空筛选、乱滑、点不动）**。
   两道防线，缺一不可：
   - `installer\build_exe.spec` 里剔除 `PyQt5\Qt5\bin\` 下那 4 个旧运行库，并从
     `C:\Windows\System32` 补齐一整套到包根（构建期，治本）；
   - `gui\app.py` 冻结分支用 `ctypes.WinDLL(完整路径)` 显式预载正确那套（运行期，防顺序再变）。
   **别删这两段代码**；打完包用 `data\gui_boot.log` 的「全包同名运行库扫描」复核只有 1 套。
5. **两个 exe 共用同一份 `_internal`；`tools\` 放 exe 同级且不编译进包**（2026-09-13 新增）。
   - `校准工具.exe` 是第二个 Analysis + 第二个 EXE，但只进**同一个** `COLLECT`：
     COLLECT 按目标路径去重，所以 cv2(98MB) / PyQt5(75MB) / onnxruntime(35MB) 不会翻倍
     （整包 306MB → 312MB，只多了两个 exe 本体）。**别拆成两个目录**（那会变 550MB+）。
   - `tools\` 由 bat 拷成 **exe 同级的普通文件**，入口用 `runpy.run_path` 执行。
     原因：所有工具都用 `Path(__file__).parent.parent` 当项目根去找 `config\`，
     编译进 PYZ 会算成 `_internal`（全盘错位）。保持普通文件还有个好处：
     **改标定判据存盘即生效，不用重打包**。
     ⚠️ 边界要记清：只有 `tools\*.py` 是这样。**改 `installer\calib_entry.py`（菜单/入口）必须整包重编译**
     —— 它是入口脚本、被编译进 `校准工具.exe`，`nobuild` 刷新不出来
     （2026-09-13 实测：菜单里看不到新增的三项，排查半天是这里）。
     ⇒ 所以 spec 里**故意没有** `collect_submodules("tools")`，别"好心"加上。

## 3. 拷到目标电脑

1. 整个 `运满满抢单机器人` 文件夹拷过去（放哪都行，别放只读目录）。
2. 目标机需要**先装好并登录**：iMouse 控制台（默认路径 `D:\iMousePro\iMouseManager.exe`），
   且手机 AirPlay 投屏在线（iMouse 控制台里能看到手机画面）。
3. 双击 `运满满抢单机器人.exe`（或 `启动.bat`）→ 过一次 UAC → GUI 出现。
4. 点 GUI 里的「启动」开始跑单。
   - 程序会自动拉起 iMouse 控制台并左右并排（`config\runtime.json` 的
     `startup.open_imouse_console` 可关闭；`console_width_ratio` 调宽度比例）
   - 想改 iMouse 路径就改 `startup.imouse_console_exe`
5. 需要标定 / 排障时，双击 **`校准工具.exe`**（控制台菜单，**不提权**）：
   归位 / 测下压深度 / 映射标定 / 复检 / 单步探针 / iMouse 探活 / UI 落点校准 /
   **整屏网格三件套**（只验连通 --dry / 离线自测 / 正式跑）。
   也可直接带参调用：`校准工具.exe tap --list`、`校准工具.exe verify`、
   `校准工具.exe run calibrate_z_press.py --hardware config\hardware.json`。
   - **判据**：能进菜单；`校准工具.exe tap --list` 能列出 5 个目标
     （这条同时证明 `_internal`、`tools\`、`config\` 三块都齐、OCR 链也是通的）。
   - 详细校准流程见 `docs\新电脑_校准指南.md`。

> 注意：`startup.imouse_console_exe` 是**绝对路径**，目标机路径不同就要改；
> 留空则用内置默认值。

## 4. 常用改动位置

| 想改什么 | 改哪里 |
|---|---|
| 路线（出发地→目的地、跑哪条） | GUI「路线」页，或 `config\routes.json` |

## 5. 常见报错

| 现象 | 原因与处理 |
|---|---|
| 双击后弹「配置错误」窗 | exe 同级缺 `config\`。正常会自动从 `_internal\config_default` 补齐；若仍报错，手动把源码的 `config\` 整份拷过去 |
| 界面顶部出现红色「⚠ OCR 引擎未加载」 | 先看 `data\gui_boot.log` 的「③ onnxruntime」行：若是 `IMPORT_FAIL` 且提到「初始化例程失败」，就是下面的 VC 运行库冲突（不是模型没打进去）。若报「找不到模型」，才查 `_internal\rapidocr_onnxruntime\models` 里的 .onnx 是否被打进去 |
| 报 `ImportError: DLL load failed while importing onnxruntime_pybind11_state: 动态链接库(DLL)初始化例程失败` | **根因（2026-09-13 查实）**：PyQt5 自带旧版 MSVCP140 在 `_internal\PyQt5\Qt5\bin\` 先占坑，与 onnxruntime 冲突。看 `data\gui_boot.log` 的「② 全包同名运行库扫描」——正常**只该有 1 套**（都在 `_internal\` 根）；若出现 `PyQt5\Qt5\bin\` 那套，说明 spec 的过滤没生效，按约定 4 检查后重新打包 |
| 页面判定/卡片匹配全不准 | `data\templates\` 缺失或被删 → 从源码拷回（或删掉整个 `data\templates` 后重启，会自动从 `_internal\templates_default` 补齐） |
| 截图/日志找不到 | 它们都在 **exe 同级**的 `data\` 下，不在 `_internal\` 里；`data\gui_boot.log` 记录启动过程 |
| 双击没反应（无窗口、无报错） | 看 `data\gui_boot.log`；若为空说明根本没起来，改用命令行 `启动.bat` 或 `cmd` 里直接跑 exe 看报错 |
| 提示找不到 iMouse 控制台 | 目标机没装或路径不同 → 改 `config\runtime.json` 的 `startup.imouse_console_exe`，或把 `open_imouse_console` 设 false 手动开 |
| 自己写脚本时同样报 1114，但 GUI 正常 | 导入顺序问题：**先 `import PyQt5` 再 `import onnxruntime` 必然失败**（PyQt5 自带旧版 MSVCP140 抢占）。改成先 import onnxruntime。`tools\check_deps.py` 已显式把 onnxruntime 提到最前（2026-09-13 修；此前它会把"环境明明是好的"误报成"装不上"，差点带偏新电脑部署） |

## 5.1 点击落点残差补偿 tap_correction（2026-09-13 新增）

- **配置**：`config\hardware.json` → `calibration.tap_correction`
  （`enabled` / `radius_px` / `points[{name,x,y,dx,dy}]`），供应商盘同款即可。
- **生效点**：`core\devices\arm.py::click_pixel()`（全工程点击唯一收口）——点击前按
  "半径内最近锚点"平移几 pt，并打印 `点击像素 (98,764) 补偿[city_clear -6,+0] -> (92,764) …`。
  `hardware.json` 在 `RESTART_REQUIRED_SECTIONS` 内 → **改完热重载即生效，不必重启**。
- **为什么需要**：墨点画布只覆盖 y≈170~660，屏幕底部按钮行靠模型外推，实测统一偏左 6~7pt；
  不补就会出现"校准工具能点到、正式运行点了没反应"（工具会扫点，运行只点一次）。
- **写入方式**：`校准工具.exe tap <目标>` 测完按提示选 Y，或 `校准工具.exe tap --apply-all`
  （读 `data\ui_tap_calib.json`，偏移 ≥2pt 建锚点、≤1pt 清除旧锚点）。**默认仍只测量**。
- **容错**：解析失败/机型不符（≠375x812）/补偿后越界，都会**自动降级为不补偿**并告警——
  这段代码在每次点击的必经路径上，任何情况下都不允许抛异常。

## 5.2 城市面板网格扫描参数（2026-09-13 新增）

- `config\runtime.json` → `swipe.grid_*`：`grid_distance_ratio`(0.12 屏，≤ 省 ROI 高度一半，
  保证不漏行) / `grid_duration_ms_range`([180,260]ms，与 _note_overlap 的 0.54 屏/秒同量级，
  避免"小幅度+长时长"被 iOS 当成拖拽而滑不动) / `grid_max_swipes`(12) / `grid_move_epsilon`(0.35) /
  `grid_escalate`(1.6) / `grid_max_step_ratio`(0.5) / `grid_top_down_ratio`(0.12)。
- 代码侧：`core\flow\actions.py::ensure_text_visible()`（阈值化位移校验 + 无位移先升幅 +
  连续 2 次才判到底 + 失败打印本屏可见文字）与 `core\flow\city_picker.py`
  （三级网格用它 + 扫描前**先归顶** + 选省前**先回省级根层级**）。
- 现场诊断：`校准工具.exe run city_grid_scan.py 江苏`（只读，逐步打印层级/幅度/位移/命中）。

## 5.3 整屏网格标定（2026-09-13 新增）

- **是什么**：手机 App（`ios_calib/`，原生 SwiftUI）当触摸传感器，电脑端 `tools\calibrate_full_grid.py`
  驱动机械臂在整屏 45 点上逐点下压，App 上报**真实落点** → 重拟合 `actuation`、重算 `arm_range`、
  生成整屏 `tap_correction` 锚点。整屏无死角、无页面状态依赖、无步长量化（一步到位修掉
  "屏幕底部按钮整体偏左 6~7pt"）。
- **端口 8767**（8765=老网页版、8766=z 扫描）；电脑端监听 `0.0.0.0`，手机填 `http://<本机IP>:8767`。
  防火墙需放行入站 8767；iOS 侧需 ATS `Allow Local Networking` + 本地网络用途描述（见 `ios_calib/README.md`）。
- **默认只测量**，`--apply` 才写配置（写前备份 `hardware.json.bak_grid`，并**丢弃旧映射下测的其它来源锚点**，
  避免方向失效——想保留加 `--keep-foreign-anchors`）。
- **关键设计（别改错）**：锚点必须用"**新模型复压一轮后**的残差"来建。refit 出的新模型已经吸收了
  系统性偏差；若用第 1 轮残差建锚点，运行时会**补两次**（离线自测复现过：5.8pt 被补成反方向 5.8pt）。
- **离线自测**：`校准工具.exe gridselftest`（= `py -3.11 tools\calib_mock_phone.py`）——
  假手机 + 假机械臂真跑 HTTP 协议，13 项断言覆盖采样/拟合/两层补偿分工/写盘/备份，
  且**真实配置零改动**。真机之前先跑它。
- `arm_range` 的重算实现已从 `calibrate_arm_ink.py` 迁到 `tools\calib_common.py`
  （`arm_range_from_model` / `write_arm_range_from_model`），两个工具共用；`calib_common.py`
  是固化文件，改完仍需 `calibrate_arm_ink.py --verify-only` 复检。
- **arm_range 自动同步 + 手动补救入口**（2026-09-13 修）：映射标定/整屏网格达标写盘时会顺手
  按新模型重算并写回 `arm_range`；若那次同步失败或被中断（配置会停在"新 actuation + 旧
  arm_range"的危险状态，即 2026-09-10"返回箭头点不到"的成因），用
  `校准工具.exe run calibrate_arm_ink.py --sync-arm-range` 秒级补同步（不取帧、不驱臂）。
  代码侧：`_report()` 的 `width/height` 必须由调用方传入（早先在函数体里写成裸变量导致
  NameError，把一次达标标定以异常收尾），且同步失败**只告警**、不影响返回码。

`core/vision/matcher.py::find()` 第一行就是 `if not spec.enabled: return None`，

- 修 path **不改变任何运行行为**，也不会让"兜底点击"重新生效；
- 所以**不需要**重跑模板基线、也不用担心引入新误判（此前写的"会改变识别行为需重跑基线"有误，已更正）；
- 将来若要重新启用某条，必须先按当前投屏空间（iPhone X，375x812）**重采模板图**并重跑基线定阈值。

（此前判断的"城市面板等兜底路径静默失效"，真正原因是 `enabled:false` —— 迁移到投屏后**有意停用**，
不是 path 写错。）

## 7. 重新打包前的自检清单
